## 1. Chapter 20 핵심 개념 정리

### 1) 실행 전 코드 읽기 및 요구사항 대조
* **핵심 명제:** "코드 오류 없이 실행된다"와 "요구사항대로 올바르게 동작한다"는 별개의 문제임.
* **코드를 먼저 읽는 순서:**
  1. **입력:** 어떤 값을 받는가? 어떤 자료형으로 바꾸는가?
  2. **처리:** 어떤 조건식, 반복문, 계산식이 적용되는가?
  3. **출력:** 무엇을 화면이나 파일에 내보내는가?
  4. **낯선 코드:** 배우지 않은 문법·모듈·함수가 있는가?

### 2) 3가지 테스트 입력 설계
1. **정상값:** 평소에 자주 입력될 일반적인 값 (예: `40000`, `60000`)
2. **경계값:** 조건이 바뀌는 지점 주변의 값 (예: 기준이 `50000`일 때 $\rightarrow$ `49999`, `50000`, `50001`)
3. **비정상값:** 허용 여부를 검증할 값 (예: `-1000`, `"오만원"`)

### 3) 올바른 디버깅 프로세스
* **절차:** 문제 재현 $\rightarrow$ 범위 축소 (단일 함수) $\rightarrow$ AI에 최소 수정 요청 $\rightarrow$ 이전 정상값까지 재검증
* **AI 디버깅 요청 시 전달할 4가지:**
  1. 현재 코드
  2. 문제가 발생한 입력 값
  3. 실제 결과
  4. 예상 결과

### 4) 디버깅 vs 코드 개선 (리팩터링)
* **디버깅:** 잘못된 동작(논리 오류)을 올바르게 고치는 작업.
* **개선(리팩터링):** 정확성을 유지하면서 변수/함수명 명확화, 중복 제거, 복잡성 감소를 통해 가독성을 높이는 작업.

## 2. 주요 Q&A 및 파이썬 문법 정리

### Q1. `else` 없이 `return`하는 방식 vs `else`를 사용하는 방식
```python
# 1. Early Return (else 생략)
def calculate_shipping(order_amount):
    if order_amount >= 50000:
        return 0
    return 3000

# 2. else 사용
def calculate_shipping(order_amount):
    if order_amount >= 50000:
        return 0
    else:
        return 3000
        ### Q1. `else` 없이 `return`하는 방식 vs `else`를 사용하는 방식
* **Early Return (else 생략):** 들여쓰기가 줄어들고 코드가 간결해짐.
* **`else` 사용:** "참일 때"와 "거짓일 때"의 분기 구조가 한눈에 잘 들어와 가독성이 높아짐.

### Q2. `tests = [(40000, 3000), (50000, 0)]` 자료구조
* 소괄호 `()`를 사용했으므로 `set`이 아니라 **`tuple`(튜플)** 임.
* **구조:** "튜플들을 원소로 가지는 리스트".
* **`tuple` 사용 이유:** (입력값, 예상값)의 순서가 보장되고 데이터가 변경되지 않기 때문.

---

### Q3. 파이썬 주요 괄호 및 자료구조 구분
* **소괄호 `()`:** `tuple` (튜플 - 순서 있음, 수정 불가)
* **대괄호 `[]`:** `list` (리스트 - 순서 있음, 수정 가능)
* **중괄호 `{}`:**
  * `{1, 2, 3}` $\rightarrow$ `set` (집합 - 순서 없음, 중복 불가)
  * `{"a": 1}` $\rightarrow$ `dict` (딕셔너리 - Key-Value 쌍)
  * `{}` (빈 중괄호) $\rightarrow$ **`dict`로 인식됨** (빈 set은 `set()` 사용)
