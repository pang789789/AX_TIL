## 1. Chapter 02. 데이터와 DBMS의 기본 개념

### 1.1 데이터 흐름 및 핵심 구조
* **시스템 구조 흐름:**  
  `사용자` → `DBeaver (클라이언트)` → `PostgreSQL (DBMS)` → `데이터베이스` → `스키마` → `테이블` → `행과 열`
* **클라이언트와 DBMS의 역할 구분:**
  * **DBeaver (클라이언트):** SQL을 작성·전달하고 실행 결과를 화면에 표시하는 UI 도구.
  * **PostgreSQL (DBMS):** 데이터를 실제 보관하고 SQL을 해석 및 실행하는 백엔드 엔진.
  * **핵심:** DBeaver를 종료하더라도 PostgreSQL 서버가 동작 중이면 데이터는 그대로 유지됨.

---

### 1.2 식별자 및 키(Key)의 개념
* **업무 식별자 vs 내부 식별자 분리 이유:**
  * **업무 식별자 (학번, 회원번호 등):** 현실 세계의 관리 정책 및 규칙 변경에 영향을 받음.
  * **내부 식별자 (`id` 등):** DB 내부 고유 행 식별용. 업무 정책 변화와 무관하게 시스템 안정성 확보.
  * **분리 목적:** 변하기 쉬운 업무 규칙과 절대로 변하면 안 되는 DB 내부 구조를 분리하여 유연성과 데이터 통합성 유지.
* **외래키(FK) 참조 원칙:**
  * 외래키는 데이터 변경 및 수정 위험이 적은 **내부 식별자**를 참조하는 것이 기본 원칙임.

---

### 1.3 관계(Relationship) 및 카디널리티(Cardinality)
* **카디널리티 개념:** 두 테이블 간의 행(Row) 대응 수량 관계 ($1:1$, $1:N$, $N:M$).
* **1:1 관계의 테이블 분리 이유:**
  * 기본적으로 1:1 관계는 하나의 테이블로 합치는 것이 원칙이나, 다음 상황에서는 분리함.
    1. **보안 및 권한 관리:** 민감 정보(주민번호, 계좌 등)의 접근 권한 제어.
    2. **성능 최적화:** 대용량 열(텍스트 본문, 첨부파일 등) 분리로 조회 속도 향상.
    3. **NULL 방지:** 특정 행에만 제한적으로 존재하는 데이터의 공간 낭비 방지.
* **N:M 관계의 연결 테이블 처리 (`students` 1 ── N `enrollments` N ── 1 `courses`):**
  * RDBMS는 $N:M$ 관계를 직접 다룰 수 없으므로, 중간에 연결 테이블(`enrollments`)을 두어 두 개의 $1:N$ 관계 구조로 해소함.
  * **주요 용어:**
    * `students`: 학생 목록
    * `courses`: 강의/과목 목록
    * `instructors`: 강사 목록
    * `enrollments`: 수강신청 이력 (학생-강의 연결)

## 2. VS Code 및 개발 환경 구축 (데이터 분석)

### 2.1 환경 구축 핵심 목표
* **재현 가능한 환경 구성:** 컴퓨터 전체 Python 환경과 독립된 프로젝트 전용 가상환경(`.venv`) 사용.
* **경로 및 인터프리터 일치:** Terminal, VS Code Python 인터프리터, Jupyter Notebook 커널이 동일한 `.venv`를 가리키도록 설정하여 `ModuleNotFoundError` 및 `FileNotFoundError` 방지.
* **실행 환경 검증 명령:**
  * `sys.executable`: 현재 실행 중인 Python 인터프리터 경로 확인.
  * `Path.cwd()`: 현재 작업 디렉토리(Current Working Directory) 위치 확인.
* **보안 관리:** API Key 등 민감 정보는 `.env` 파일로 관리하며, `.gitignore`에 추가해 Git 저장소 유출 차단.
