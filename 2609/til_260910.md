## 2. 데이터 분석 & 머신러닝 전체 파이프라인

데이터 분석부터 미래 예측까지 연결되는 표준 파이프라인 속에서 전처리의 위치와 중요성을 확인했다.

[1. 과거 데이터] ➔ [2. EDA 및 전처리] ➔ [3. 기계학습 모델링] ➔ [4. 미래 예측 및 활용]
 (CSV / DataFrame)   (pandas / 시각화)     (회귀 / 분류)        (비즈니스 의사결정)

1. 과거 데이터 수집 (data/raw): 원천 DB/CSV 파일 로드 및 원본 보관
2. EDA & 데이터 전처리 (pandas): 데이터 요약 및 정제 (data/processed). 파이프라인의 70~80% 비중을 차지하며 GIGO(Garbage In, Garbage Out)를 방지하는 가장 결정적인 단계
3. 기계학습 (Machine Learning): 회귀(연속된 숫자 예측) 및 분류(범주/그룹 예측) 모델 학습
4. 미래 예측 및 활용: 정제된 데이터 기반 예측을 통한 실제 비즈니스 전략 수립

## 3. 핵심 질문과 개념 정리 (Q&A)

### Q1. Series와 DataFrame은 어떻게 구분하나요?
* Series (시리즈): 1차원 데이터 구조. 단일 열(Column)로 구성되며, 인덱스와 값의 1:1 매핑.
* DataFrame (데이터프레임): 2차원 데이터 구조. 여러 개의 Series가 모여 만들어진 가로x세로 격자형 표.
* 출력 모양 및 대괄호 구분:
  - 상단 컬럼명이 있고 행/열이 모두 보이면 DataFrame
  - 컬럼명 없이 인덱스와 값만 보이고 맨 아래 Name: ..., dtype: ...이 표시되면 Series
  - df["age"] (대괄호 1개) ➔ Series 반환
  - df[["age"]] (대괄호 2개) ➔ DataFrame 반환

### Q2. 전체 변수를 부른 type(customers)는 왜 DataFrame인가요?
* customers 변수 자체가 여러 개의 열(Series)과 행을 포함하는 2차원 표 전체를 담고 있기 때문.

[코드 예시]
type(customers)             # pandas.core.frame.DataFrame (전체 표)
type(customers["age"])      # pandas.core.series.Series (1개 열 추출)
type(customers[["age"]])    # pandas.core.frame.DataFrame (2차원 표 형태 유지)

### Q3. 나이(age) 결측치를 중앙값으로 채우면 어떤 문제가 생기나요?
* 부작용 발생!
  1. 분포 왜곡 (분산 감소): 인위적인 대표값 채우기로 표준편차가 줄어들고 그래프가 특정 위치에서 이상할 정도로 높게 솟음.
  2. 관계 왜곡: 다른 변수(구매 금액, 선호 상품 등)와의 상관관계가 왜곡됨.
  3. 정보 손실: "왜 입력하지 않았는가"에 대한 비즈니스적 맥락이 손실됨.
* 실무적 대안:
  - 결측 비율이 매우 적은 경우 행 삭제 (dropna)
  - 정보 손실 방지를 위해 'Unknown(미상)' 범주 유지
  - 전체 중앙값 대신 '성별/지역별 그룹 중앙값'으로 조건부 대체

### Q4. 파생 컬럼(Derived Column)이란 무엇인가요?
* 기존 컬럼을 연산하거나 조건문·함수를 적용해 새롭게 만든 컬럼.

[코드 예시]
# 수식 연산: 구매 수량 x 단가
order_items["line_total"] = order_items["quantity"] * order_items["unit_price"]

# 날짜 추출: 연-월 파생 컬럼
orders["order_year_month"] = orders["order_date"].dt.strftime("%Y-%m")

## 4. 권장 전처리 절차 및 원칙

1. 원본 보존: data/raw 원본 보관 및 df.copy()로 작업용 복사본 생성
2. 초기 상태 기록: 전처리 전 행 수, 결측치 수 기록
3. 문자열 정리 & 통일: .str.strip() 적용 및 빈 문자열, "N/A" 등을 pd.NA로 통일
4. 타입 변환 & 실패 추적: pd.to_numeric(..., errors="coerce") 적용 후 늘어난 새 결측치(변환 실패 원본 값) 추적
5. 결측치·중복·범주 표준화: 비즈니스 기준에 맞춰 처리 후 보류 행은 data/rejected/에 보관
6. 저장 및 보고서 작성: 정제된 데이터를 data/processed/에 저장하고 전후 품질 변화 기록
