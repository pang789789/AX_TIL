## 오늘의 학습 주제

오늘은 Chapter 14-1의 **데이터 분석 자동화 입문** 수업을 진행했다. 지금까지 각각 실행했던 API 수집, pandas 분석, 시각화, LLM 요약 과정을 하나의 반복 가능한 흐름으로 연결하는 방법을 배웠다.

이번 장의 자동화는 두 가지 방식으로 나뉜다.

```text
PART 1: 내 PC → Python → API → pandas → LLM → PDF → 작업 스케줄러

```

두 방식은 같은 관광 트렌드 분석 업무를 다루지만 서로 직접 연결하지 않는다. 로컬 Python이 만든 PDF를 Make로 보내거나, Make가 내 PC의 Python 파일을 실행하는 구조가 아니다. 코드 기반 자동화와 노코드 기반 자동화를 각각 경험하고 차이를 이해하는 것이 목적이다.

## 수업 전 서비스 준비

실습에 필요한 서비스의 용도를 확인하고 회원가입 및 사용 준비를 했다.

### NAVER Cloud Platform

- 사이트: [NAVER Cloud Platform](https://www.ncloud.com/)
- 용도: NAVER Search Trend API 사용
- Client ID와 Client Secret을 발급받아 Python 또는 Make의 HTTP 요청에 사용한다.

NAVER Trend API에서는 `여행`, `축제`, `캠핑`, `맛집` 키워드의 월별 검색 관심도를 조회한다. 여기서 `ratio`는 실제 검색 횟수가 아니라, 조회 기간의 최대 검색량을 100으로 둔 **상대 지수**다.

따라서 `여행 80`, `축제 40`이라는 결과가 나와도 여행 검색 건수가 정확히 두 배라고 해석하면 안 된다. 같은 조회 조건에서 여행의 상대적인 검색 관심도가 더 높았다고 표현해야 한다.

### 공공데이터포털

- 사이트: [공공데이터포털](https://www.data.go.kr/)
- 사용 API: 한국관광공사 지역별 관광 수요 강도
- 용도: 지역별 관광 체류 강도 및 관광 소비 강도 조회

공공데이터포털에서 로그인한 뒤 활용신청, 개발계정 신청, 승인 확인, Service Key 확인 순서로 진행했다. API 상세 페이지의 Swagger UI를 이용하면 Python 코드를 작성하기 전에 요청 URL과 필수 파라미터, 응답 형식을 직접 시험할 수 있다.

Swagger에서 확인한 주요 요청 조건은 다음과 같다.

```json
{
  "stay": {
    "params": {
      "MobileOS": "ETC",
      "MobileApp": "chapter14-1",
      "_type": "json",
      "baseYm": "202508",
      "areaCd": "11",
      "tarSjrnDsIxCd": "21"
    }
  },
  "consumption": {
    "params": {
      "MobileOS": "ETC",
      "MobileApp": "chapter14-1",
      "_type": "json",
      "baseYm": "202508",
      "areaCd": "11",
      "tarExpDsIxCd": "22"
    }
  }
}
```

이 값은 API Key가 아니라 조회 조건이므로 `config/tourism_params.json`에 저장한다. 반대로 Service Key와 각종 인증 정보는 `.env`에 저장해야 한다.

### LLM API

수업에서는 OpenAI, Google Gemini, Anthropic Claude 중 하나 이상의 계정만 준비하면 된다. 모든 서비스를 동시에 가입할 필요는 없다. 오늘은 OpenAI를 사용하는 방식으로 실습 구조를 확인했다.

LLM의 역할은 계산 자체가 아니라, Python에서 검증한 분석 결과를 사람이 읽기 쉬운 문장으로 정리하는 것이다. 입력 데이터에 없는 수치나 사실을 만들지 않도록 프롬프트에 제한 조건을 명시해야 한다.

### Make

- 사이트: [Make](https://www.make.com/)
- 용도: 클라우드 기반 노코드 자동화

Make에 가입하고 Scenario를 만드는 화면을 사용해 보았다. Make에서는 여러 모듈을 선으로 연결하여 자동화 흐름을 만든다.

```text
Scheduler → NAVER HTTP → 관광 API HTTP → LLM → Gmail
```

처음부터 예약 실행을 켜는 것이 아니라, 모듈을 하나씩 추가한 뒤 `Run once`로 Input과 Output Bundle을 확인해야 한다. 모든 모듈이 원하는 데이터를 전달하는 것을 확인한 다음 Schedule을 활성화한다.

### 2. 프로젝트 구조 만들기

실습 파일을 역할별로 분리했다.

```text
chapter14-1/
├─ config/
├─ data/
│  ├─ raw/
│  └─ processed/
├─ logs/
├─ reports/
└─ src/
```

- `config`: API 요청 조건
- `data/raw`: API 원본 응답 JSON
- `data/processed`: 분석하기 좋게 가공한 CSV
- `logs`: 자동화 실행 기록
- `reports`: 그래프, 요약문, PDF 등의 최종 결과
- `src`: 수집·분석·보고서 생성 코드

원본 데이터와 가공 데이터를 분리하면 오류가 생겼을 때 API 응답부터 다시 확인할 수 있고, 어느 단계에서 문제가 생겼는지 추적하기 쉽다.

### 3. Secret과 설정 파일 분리

API Key는 Python 코드나 JSON 설정 파일에 직접 작성하지 않고 `.env`에 저장한다. 저장소에 올라가면 안 되는 항목은 `.gitignore`에 등록한다.

```gitignore
.venv/
.env
__pycache__/
*.pyc
logs/
data/raw/
```

실제 값이 없는 `.env.example`은 필요한 변수 이름을 공유하는 용도로 사용한다. 키가 설정됐는지 확인할 때도 실제 값을 출력하지 않고 `CONFIGURED` 또는 `MISSING`만 표시해야 한다.

프로젝트 루트의 환경변수와 Chapter 14-1의 환경변수가 섞이지 않도록 수업 폴더 안의 `.env`를 명시적으로 읽었다.

```python
BASE_DIR = Path(__file__).resolve().parents[1]
load_dotenv(BASE_DIR / ".env")
```

### 4. NAVER Trend 데이터 수집

NAVER Search Trend API에 POST 방식으로 요청했다.

```text
https://naverapihub.apigw.ntruss.com/search-trend/v1/search
```

요청에는 시작일, 종료일, 월 단위 조회 조건, 키워드 그룹을 포함한다. 응답 원본은 `data/raw`에 JSON으로 저장하고, `period`, `keyword`, `ratio`만 정리한 결과는 `data/processed/naver_trend.csv`에 저장한다.

실제 API 준비가 완료되지 않았을 때는 MOCK 데이터를 사용해 이후 분석 흐름부터 먼저 검증했다. MOCK 데이터에는 `data_source=MOCK` 표시를 남겨 실제 API 데이터와 혼동하지 않도록 했다.

### 5. 관광 API를 Swagger에서 먼저 검증

공공데이터 API는 코드부터 작성하지 않고 Swagger UI에서 먼저 실행했다. 다음 항목을 확인했다.

- HTTP Status가 정상인지
- JSON 응답이 반환되는지
- 실제 데이터가 들어 있는지
- 지역과 기간을 나타내는 필드가 무엇인지
- 체류 강도 및 소비 강도 값의 필드명이 무엇인지

HTTP 200이 나왔다고 해서 곧바로 분석 가능한 것은 아니다. 오류 메시지만 JSON으로 반환되거나, 요청은 성공했지만 데이터가 비어 있을 수도 있기 때문이다.

### 6. 관광 데이터 수집 설정

체류 강도와 소비 강도 API URL은 `.env`에 저장하고, 조회 파라미터는 `config/tourism_params.json`에 분리했다.

```env
TOURISM_SERVICE_KEY=본인의_인증키
TOURISM_STAY_URL=체류_강도_API_URL
TOURISM_CONSUMPTION_URL=소비_강도_API_URL
```

`collect_tourism.py`는 두 API를 각각 호출하여 원본 JSON을 `data/raw`에 저장한다. 데이터가 없거나 API가 오류를 반환하면 다음 단계로 넘어가지 않게 해야 한다.

### 7. pandas 분석과 그래프 생성

수집된 NAVER Trend 데이터를 pandas로 읽어 다음 내용을 확인했다.

- `period`, `keyword`, `ratio` 컬럼 존재 여부
- 결측치 존재 여부
- 날짜와 숫자 타입 변환 여부
- 키워드별 최신 관심도
- 기간별 관심도 변화

`matplotlib`을 이용하여 키워드별 검색 관심도 추이 그래프를 만들고 `reports/naver_trend.png`로 저장했다. MOCK 데이터로 만든 그래프에서도 여행, 축제, 캠핑, 맛집의 기간별 변화를 한눈에 비교할 수 있었다.

분석 결과는 `analysis_summary.csv`로도 저장했다. 표와 그래프가 생성되었다는 사실만 보는 것이 아니라, 원본 CSV의 값과 그래프의 선이 서로 일치하는지 확인하는 과정이 필요했다.

### 8. 검증된 흐름만 자동화하기

최종 파이프라인은 다음 순서로 실행된다.

```text
collect_naver.py
→ collect_tourism.py
→ analyze.py
→ generate_llm_report.py
→ generate_pdf.py
```

`run_pipeline.py`가 각 파일을 순서대로 실행하며, 한 단계라도 실패하면 뒤 단계를 실행하지 않는다. 이것을 **Fail Fast**라고 한다.

```text
NAVER 수집 실패
→ 관광 데이터 수집 중단
→ 분석 중단
→ LLM 호출 중단
→ PDF 생성 중단
```

잘못된 입력으로 보고서를 계속 만드는 것보다 첫 오류에서 멈추고 로그를 확인하는 편이 안전하다.

### 9. 반복 실행과 예약 실행

전체 파이프라인은 먼저 PowerShell에서 직접 실행하고, 결과 PDF와 로그를 확인한 뒤 같은 명령을 한 번 더 실행한다. 두 번째 실행에서는 데이터가 이유 없이 계속 추가되거나 중복 결과가 무분별하게 생성되지 않는지 확인한다.

Windows 작업 스케줄러에서는 `run_pipeline.bat`을 실행하도록 등록할 수 있다.

```bat
@echo off
cd /d "%~dp0"
".venv\Scripts\python.exe" run_pipeline.py
```

예약 실행은 편리하지만 PC가 꺼져 있으면 로컬 파이프라인도 실행되지 않는다는 한계가 있다.

## PART 2. Make 온라인 자동화 실습

### 1. Scenario 구성

Make에서 `Tourism Trend Weekly Report` Scenario를 만들고 다음 흐름을 구성하는 방법을 확인했다.

```text
Scheduler
→ HTTP: NAVER Trend API
→ HTTP: 관광 API
→ LLM
→ Gmail
```

Make는 내 PC가 아니라 클라우드에서 실행되므로 PC가 꺼져 있어도 예약 실행할 수 있다. 반면 pandas를 이용한 복잡한 분석보다는 간단한 값 전달과 업무 자동화에 적합하다.

### 2. HTTP 모듈 사용

NAVER API는 POST 요청으로 호출하며 인증 헤더와 JSON Body를 설정한다. 관광 API는 Swagger에서 성공했던 URL과 Query String을 그대로 사용한다.

각 HTTP 모듈을 추가한 뒤 `Run once`를 실행하여 다음을 확인한다.

- HTTP Status
- 응답 JSON 구조
- 필요한 데이터가 실제로 포함됐는지
- 다음 모듈로 전달되는 값이 올바른지

Make 화면에 초록색 성공 표시가 나타나는 것과 데이터 검증이 끝났다는 것은 다른 의미다. 반드시 각 모듈의 Input과 Output Bundle을 직접 열어봐야 한다.

### 3. LLM과 Gmail 연결

LLM에는 원본 JSON 전체를 무작정 전달하기보다 분석 기준일, 최신 검색 관심도, 대표 관광 수요 값, 데이터의 의미와 해석 제한을 전달한다.

프롬프트에는 다음 원칙을 포함한다.

- 입력에 없는 숫자와 사실을 만들지 않는다.
- 검색 관심도를 실제 검색 건수로 표현하지 않는다.
- 함께 변한 항목을 인과관계로 단정하지 않는다.
- 추가 확인이 필요한 부분을 별도로 작성한다.

마지막 Gmail 모듈에서는 Google 계정을 연결하고 LLM 결과를 이메일 본문에 매핑한다. `Run once`로 본인 메일에 정상 도착하는지 확인한 뒤에만 Scheduler를 활성화한다.

짧은 주기로 예약하면 API 호출량, Make Credit, LLM 비용, 중복 메일이 늘어날 수 있으므로 필요한 주기로만 설정해야 한다. 시간대도 `Asia/Seoul`인지 확인한다.

## 오늘 배운 핵심

### API 호출 성공과 분석 성공은 다르다

HTTP 200은 서버가 요청을 처리했다는 뜻일 뿐, 필요한 데이터가 정확히 들어 있다는 보장은 아니다. 응답 구조, 데이터 개수, 결측치, 타입, 기간, 단위를 함께 확인해야 한다.

### 자동화 전에 수동 검증이 먼저다

```text
수동 실행 → 결과 확인 → 오류 수정 → 재실행 → 정상 확인 → 자동화
```

검증되지 않은 작업을 자동화하면 오류도 빠르고 반복적으로 생산된다. 자동화의 목적은 사람의 검증을 없애는 것이 아니라, 검증이 끝난 반복 작업을 안정적으로 수행하는 것이다.

### 분석 단위가 다른 데이터는 억지로 합치지 않는다

NAVER Trend는 전국 수준의 검색 관심도를 나타내고, 관광공사 데이터는 지역별 체류·소비 강도를 나타낸다. 공통 기간과 동일한 분석 단위가 확인되지 않았다면 행 단위로 무조건 `merge`하지 않고 각각 분석한 뒤 하나의 보고서에서 함께 해석한다.

### Python과 LLM의 역할은 다르다

Python은 계산, 정렬, 집계, 검증처럼 결과가 명확해야 하는 작업을 담당한다. LLM은 검증된 값을 바탕으로 요약문과 설명을 작성한다. LLM이 자연스러운 문장을 만들더라도 그 내용이 자동으로 사실이 되는 것은 아니므로 사람이 다시 확인해야 한다.

### Secret은 코드와 분리한다

API Key, Client Secret, Service Key는 `.env`에 저장하고 Git에 올리지 않는다. 화면을 캡처하거나 결과를 공유할 때도 인증키와 개인정보가 노출되지 않았는지 확인해야 한다.

| 예약 실행 | Windows 작업 스케줄러 | Make Scheduler |
| API 호출 | `requests` | HTTP 모듈 |
| 분석 | pandas로 상세 분석 | 간단한 값 처리와 전달 |
| LLM 연결 | SDK 또는 API | 앱 또는 HTTP 모듈 |
| 결과 | 그래프와 PDF | Gmail 보고서 |
| PC가 꺼진 경우 | 실행되지 않음 | 실행 가능 |

## 느낀 점

처음에는 자동화라고 하면 코드를 한 번에 실행하거나 정해진 시간에 프로그램을 켜는 것만 생각했다. 오늘 실습을 통해 자동화에서 더 중요한 것은 **각 단계의 입력과 출력을 검증하고, 실패했을 때 정확한 위치에서 멈추게 만드는 것**이라는 점을 알게 되었다.

NAVER Trend의 `ratio`가 실제 검색 건수가 아니라 상대 지수라는 점도 인상적이었다. 그래프가 보기 좋게 만들어져도 지표의 정의를 잘못 이해하면 전혀 다른 결론을 낼 수 있다. 앞으로 새로운 API를 사용할 때는 코드보다 공식 문서와 응답 필드의 의미를 먼저 확인해야겠다.

공공데이터포털의 Swagger UI를 이용해 본 것도 도움이 되었다. Python 코드에서 오류를 찾기 전에 웹 화면에서 URL, 인증키 전달 방식, 필수 파라미터와 응답을 확인하면 문제 범위를 빠르게 줄일 수 있었다.

Make는 코드를 직접 작성하지 않아도 Scheduler, HTTP, LLM, Gmail을 화면에서 연결할 수 있어 반복적인 알림이나 정기 보고 업무에 유용해 보였다. 다만 모듈이 초록색으로 표시됐다고 결과가 올바른 것은 아니었다. 편리한 도구일수록 Input과 Output Bundle을 직접 확인하는 습관이 필요하다고 느꼈다.

또한 API 키를 `.env`로 분리하는 이유를 실제 실습 과정에서 체감했다. 인증 정보를 코드나 캡처 화면에 노출하면 다른 사람이 사용할 수 있고 비용이나 보안 문제가 발생할 수 있다. 앞으로는 키의 실제 값을 출력하지 않고 설정 여부만 확인하며, 노출된 키는 즉시 폐기하고 재발급받아야겠다.
