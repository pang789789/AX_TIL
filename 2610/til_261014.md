## 오늘 한 일

### 1. HTML과 CSS 실습 환경 준비

- VS Code에서 수업용 프로젝트의 Chapter 폴더를 열었다.
- `index.html`과 `style.css`를 만들고 HTML에서 CSS 파일을 연결했다.
- HTML 문서의 기본 구조를 작성했다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Member Management</title>
    <link rel="stylesheet" href="style.css">
</head>
<body>
</body>
</html>
```

`<link rel="stylesheet" href="style.css">`는 HTML 문서가 같은 폴더의 `style.css`를 사용하도록 연결하는 코드다. CSS 파일을 만들기만 하고 이 연결을 빠뜨리면 스타일이 적용되지 않는다.

### 2. CSS 주석 작성 방법 확인

HTML과 CSS의 주석 문법이 다르다는 점을 확인했다.

```html
<!-- HTML 주석 -->
```

```css
/* CSS 주석 */
```

CSS에서 `#`은 주석 표시가 아니다. `#signup-form`처럼 아이디 선택자를 작성하거나 `#f8fafc`처럼 Hex 색상을 표현할 때 사용된다. 따라서 CSS 설명을 남길 때는 반드시 `/* ... */`를 사용해야 한다.

### 3. 태그·클래스·아이디 선택자 학습

CSS 선택자는 어떤 HTML 요소에 스타일을 적용할지 정하는 문법이다.

#### 태그 선택자

```css
h1 {
    color: navy;
}
```

태그 선택자는 같은 태그를 가진 모든 요소에 적용된다. 위 코드는 페이지 안의 모든 `<h1>` 요소를 선택한다.

#### 클래스 선택자

```html
<section class="member-card">
    <h2>홍길동 회원</h2>
    <p>이메일: gildong@example.com</p>
</section>
```

```css
.member-card {
    background-color: white;
}
```

클래스 선택자는 이름 앞에 `.`을 붙인다. 여러 요소에 같은 이름표를 붙여 동일한 스타일을 반복 적용할 때 사용한다.

#### 아이디 선택자

```html
<form id="signup-form">
    <h3>회원가입 폼</h3>
</form>
```

```css
#signup-form {
    background-color: #f8fafc;
}
```

아이디 선택자는 이름 앞에 `#`을 붙인다. 한 페이지에서 특정한 하나의 요소를 식별할 때 사용한다.

```text
tag   = 같은 종류 전체
class = 같은 이름표를 가진 여러 요소
id    = 특정 하나의 요소
```

### 4. 색상과 배경 적용

CSS에서 `color`는 글자색, `background-color`는 배경색을 지정한다.

```css
body {
    color: #334155;
    background-color: #f8fafc;
}

header {
    background-color: #1e293b;
    color: white;
}
```

색상은 이름, Hex 값, RGB 등 여러 방식으로 표현할 수 있다.

```css
color: red;
color: #ff0000;
color: rgb(255, 0, 0);
```

Hex 값을 외우는 것이 목적은 아니다. 브라우저가 색상을 표현하는 방식 중 하나이며, 필요할 때 색상 선택 도구에서 값을 가져와 사용하면 된다.

### 5. 글꼴과 텍스트 스타일

```css
body {
    font-family: Arial, sans-serif;
}

h1 {
    font-size: 32px;
    font-weight: 700;
}

p {
    line-height: 1.6;
}
```

- `font-family`: 사용할 글꼴과 대체 글꼴을 지정한다.
- `font-size`: 글자 크기를 지정한다.
- `font-weight`: 글자 굵기를 지정한다.
- `line-height`: 줄 간격을 지정해 본문을 읽기 쉽게 만든다.

### 6. CSS 상속과 우선순위

부모 요소에 지정한 글자색이나 글꼴은 자식 요소에 상속될 수 있다. 그러나 같은 요소에 여러 규칙이 적용되면 더 구체적인 선택자가 우선한다.

```css
p {
    color: blue;
}

.notice {
    color: green;
}

#important {
    color: red;
}
```

같은 `<p>`가 `class="notice"`와 `id="important"`를 모두 가진다면 일반적인 우선순위는 다음과 같다.

```text
태그 선택자 < 클래스 선택자 < 아이디 선택자
```

여기서 1순위, 2순위, 3순위는 순위 숫자가 커질수록 강하다는 뜻이 아니라, 우선순위를 설명하기 위한 순서였다. 실제로는 아이디 선택자가 가장 구체적이어서 적용된다. 단순히 코드가 아래에 있다는 이유만으로 항상 이기는 것은 아니며, 선택자의 구체성과 선언 순서를 함께 봐야 한다.

### 7. CSS 박스 모델과 기본 배치

HTML 요소는 내용, 안쪽 여백, 테두리, 바깥 여백으로 구성된다.

```text
content → padding → border → margin
```

```css
.member-card {
    background-color: white;
    border: 2px solid #333;
    padding: 24px;
    margin-bottom: 16px;
}
```

- `padding`: 내용과 테두리 사이의 안쪽 여백
- `border`: 요소의 테두리
- `margin`: 다른 요소와 떨어지는 바깥쪽 여백

테두리를 처음에는 빨간색으로 표시해 영역을 눈으로 확인한 뒤 최종 색으로 변경하는 방법도 배웠다. 스타일 적용 전후를 비교할 때는 CSS 속성 한 줄을 주석 처리하거나 값을 크게 바꿔 보고, 브라우저를 새로고침하여 차이를 확인하면 된다.

### 9. VS Code 저장 충돌 해결

`The content of the file is newer` 오류는 편집 중인 내용보다 디스크의 파일이 더 새로 변경되었을 때 나타난다. 이 상태에서 무조건 `Overwrite`를 누르면 다른 변경을 덮어쓸 수 있다.

안전한 순서는 다음과 같다.

1. `Compare`를 눌러 내 편집 내용과 디스크 파일을 비교한다.
2. 필요한 코드를 한쪽에 합친다.
3. 확실히 현재 편집 내용을 유지해야 할 때만 `Overwrite`를 선택한다.
4. 여러 도구가 동시에 같은 파일을 수정하지 않도록 한다.

오늘은 자동 수정과 VS Code 편집이 겹치면서 `index.html`과 `style.css`에 저장 충돌이 발생했다. 앞으로는 수업 중 직접 입력하는 파일을 외부 도구가 동시에 수정하지 않게 하고, 변경 전 파일 상태를 먼저 확인해야 한다.

### 12. YES24 페이지 연결 확인

먼저 많은 데이터를 한 번에 가져오기 전에 한 페이지에 정상적으로 연결되는지 확인했다.

```python
import requests
from bs4 import BeautifulSoup

url = "https://www.yes24.com/product/category/bestseller?categoryNumber=001"
response = requests.get(
    url,
    headers={"User-Agent": "Mozilla/5.0"},
    timeout=10,
)
response.raise_for_status()

soup = BeautifulSoup(response.text, "html.parser")
```

이 코드는 YES24 베스트셀러 페이지의 HTML을 요청하고, BeautifulSoup으로 탐색할 수 있는 객체를 만드는 과정이다.

확인해야 할 항목은 HTTP 상태 코드, Content-Type, 페이지 제목이다. HTTP 200만 나온다고 원하는 데이터가 올바르게 도착했다고 단정하면 안 된다. 오류 안내 HTML이나 차단 페이지가 200으로 반환될 수도 있기 때문이다.

### 13. 책 제목·상품 ID·상세 URL 추출

목록 페이지에서 `.gd_name` 링크를 찾아 상품 상세 URL과 상품 ID를 만들었다.

```python
import re
import pandas as pd
from urllib.parse import urljoin

book_rows = []
seen_product_ids = set()

for link in soup.select("a.gd_name"):
    detail_url = urljoin(url, link.get("href", ""))
    match = re.search(r"/product/goods/(\d+)", detail_url)

    if not match:
        continue

    product_id = match.group(1)
    if product_id in seen_product_ids:
        continue

    seen_product_ids.add(product_id)
    book_rows.append({
        "title": link.get_text(" ", strip=True),
        "product_id": product_id,
        "detail_url": detail_url,
    })

books_ext_preview = pd.DataFrame(book_rows)
```

상품 ID와 ISBN은 모두 병합 식별자 후보가 될 수 있다. 다만 실제 원본 데이터와 합칠 때는 양쪽 데이터에 안정적으로 존재하는 값인지 먼저 확인해야 한다. 상품 ID는 YES24 내부 식별자이고 ISBN은 서적 자체의 표준 식별자라는 차이가 있다.

또한 공개 HTML 수집 예제의 기본 상태는 다음과 같았다.


따라서 YES24 데이터 추출 코드는 교안의 원본 코드가 아니라 수업 중 별도로 제시된 목표에 맞춰 추가한 실습이다. 교안 내용과 추가 응용 코드를 섞어서 같은 것으로 설명하면 안 된다.

## 외부 데이터 수집 원칙

### 17. 수집 가능성과 수집 허용은 다르다

```text
수집할 수 있다 ≠ 수집해도 된다
HTTP 200 ≠ 올바른 데이터
수집 성공 ≠ 분석에 사용 가능
```

공개 페이지라도 자동 접근 규칙과 콘텐츠 사용 조건을 따로 확인해야 한다.

- `robots.txt`: 자동 접근에 관한 기술 규칙
- Terms / License / Copyright / Privacy: 수집·저장·사용 조건
- 로그인, CAPTCHA, paywall, 접근 제한을 우회하지 않는다.
- 분석에 필요하지 않은 데이터는 수집 범위에서 제외한다.
- 실제 비밀번호, API Key, 개인정보를 AI 프롬프트나 Notebook에 기록하지 않는다.

### 18. 외부 데이터의 증거와 재현성

외부 데이터를 사용할 때는 값만 저장하는 것이 아니라 다음 정보도 함께 기록해야 한다.

- 제공자와 공식 출처 URL
- 수집 방법과 요청 조건
- 수집 시각
- 페이지 또는 데이터 범위
- 중복 제거 기준
- 성공·실패·정책 차단 상태
- 원본과 전처리 결과의 저장 위치
- 데이터의 대표성과 한계

Raw Snapshot은 같은 이름으로 조용히 덮어쓰지 않고, 필요하면 시각을 포함한 버전 경로를 사용한다. 그래야 결과가 바뀌었을 때 어떤 원본으로 분석했는지 추적할 수 있다.

## PostgreSQL Chapter 13 확장 실습 준비

### 19. 새로운 교안의 목적 파악

마지막에 확인한 새로운 Chapter 13 자료는 YES24 크롤링이 아니라 PostgreSQL과 DBeaver를 이용해 AI가 만든 데이터베이스 설계를 검증하는 확장 실습이었다.

```text
→ 업무 정합성 검증
→ diff 검토
→ 사람이 최종 승인
```

### 20. Chapter 13 답안 파일 준비

기존 저장소 `C:\dev\ai-database-book`에서 다음 파일과 폴더를 준비했다.

```text
assignments/chapter13/
```

원본 템플릿을 복사해 `chapter13_answer.md`를 만들었으며, 실제 비밀번호나 전체 접속 URL은 답안에 기록하지 않는다.

### 21. 격리된 검증이 필요한 이유

`course_project`는 Chapter 7·8의 기준 상태이므로 Chapter 13에서 직접 변경하면 안 된다. AI가 만든 변경 후보는 `ai_review_lab` 스키마에서 먼저 실행한다.

격리 검증의 장점은 다음과 같다.

- 기존 정상 데이터를 보호할 수 있다.
- 나쁜 설계와 좋은 설계를 같은 기준으로 비교할 수 있다.
- DROP, DELETE, CASCADE 같은 위험 변경의 영향을 제한할 수 있다.
- 테스트 실패 시 원본 프로젝트를 복구하는 부담이 줄어든다.
- AI의 제안을 승인하기 전에 실제 실행 증거를 확보할 수 있다.

### 22. 확인된 데이터베이스 요구사항

교안의 P13 요구사항은 다음과 같다.

- 학생과 강사의 이메일은 공백을 허용하지 않고 정확히 같은 문자열의 중복을 막는다.
- 강의는 강사 한 명을 외래키로 참조한다.
- 학생과 강의의 다대다 관계는 `enrollments`로 해소한다.
- 수강 상태는 허용된 값만 사용한다.
- 가격, 신청 당시 기록 금액, 결제 상태 기록 금액은 0 이상이어야 한다.
- 격리 시나리오의 결제는 수강신청을 외래키로 참조한다.
- 원시 카드번호와 CVV를 저장하지 않고 가상 결제 참조값을 사용한다.
- 신청·수강중 상태의 활성 신청은 학생과 강의 조합마다 한 건만 허용한다.

확정 요구사항과 별도로 보관 기간, 상태 전이, 이메일 대소문자 정규화, 부분 환불 같은 정책은 함부로 확정하지 않는다.

### 24. 검증해야 할 기준값

좋은 설계 생성 후 확인할 주요 기준은 다음과 같다.

반례와 정상 경계값 테스트의 최종 기준은 다음과 같다.

자동 완료 게이트의 기대 메시지는 다음과 같다.

```text

```

하지만 자동 게이트가 통과해도 요구사항 자체가 잘못되었거나 미확정 정책이 임의로 구현되었을 수 있으므로 최종 승인은 사람이 해야 한다.

## 오늘 발생한 문제와 해결 기준

### 수업 코드가 너무 길어 보였던 이유

교수자 화면의 코드는 핵심 개념만 짧게 보여주는 예제일 수 있고, 실제 실행용 코드는 오류 확인, 중복 제거, 경로 생성, 타입 변환, 예외 처리 때문에 길어진다. 학습 단계에서는 먼저 핵심 코드로 원리를 확인하고, 안정성을 위한 코드를 한 번에 모두 붙이기보다 필요성을 이해하면서 추가하는 편이 좋다.

### 앞 단계 변수가 필요한 코드

Notebook의 마지막 셀만 다른 사람에게 전달하면 `soup`, `pd`, `re`, `books_ext_preview` 등이 정의되지 않아 실행되지 않을 수 있다. 코드를 공유할 때는 다음을 확인한다.

- 필요한 라이브러리 설치
- import 문
- URL 요청과 응답 확인
- BeautifulSoup 객체 생성
- 앞 단계 DataFrame 생성
- 최종 추출과 저장

### 교안과 현장 실습이 다를 때

교안에서 직접 제공된 코드인지, 교수자가 수업 중 추가로 제시한 응용 과제인지 먼저 구분한다. 불분명하면 실행 전에 목표, 입력 데이터, 기대 출력, 저장 경로를 짧게 확인한다.

3. VS Code의 저장 충돌은 무조건 덮어쓰지 말고 먼저 비교해야 한다.

5. 전체 수집 전에 연결 확인과 한 건 테스트를 먼저 해야 한다.

9. 데이터베이스 변경은 원본 프로젝트가 아닌 격리 스키마에서 먼저 검증해야 한다.
10. 실행 성공만으로는 부족하며 메타데이터, 정상값, 경계값, 실패값, 업무 정합성, diff까지 확인해야 한다.
