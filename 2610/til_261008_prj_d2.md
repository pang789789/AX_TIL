# 2026-10-08 프로젝트 2일차 작업 기록 및 회고

## 오늘의 상황

원래 4명이 함께 진행하는 팀 프로젝트였지만, 오늘은 팀원 2명이 개인 사정으로 참여하지 못했다. 갑작스럽게 절반의 인원만 남은 상황이라 기존 담당 영역만 진행해서는 전체 작업 흐름을 유지하기 어려웠다.

남은 2명이 빠진 팀원의 작업까지 나누어 맡았고, 서로 진행 상황을 계속 공유하며 우선순위가 높은 기능부터 처리했다. 작업량은 예상보다 많았지만 기능 구현, 화면 확인, 오류 수정, Git 작업과 PR 리뷰 대응까지 함께 진행하며 프로젝트를 이어갔다.

## 오늘 한 일

### 1. 장바구니 수량 실시간 반영

- 상품을 장바구니에 담아도 헤더의 장바구니 숫자가 바로 바뀌지 않는 문제를 확인했다.
- 장바구니 상태를 공용 훅과 연결하여 상품 추가, 수량 변경, 삭제 시 헤더 숫자가 즉시 갱신되도록 수정했다.
- 비회원 장바구니와 로그인 이후의 장바구니 흐름도 함께 확인했다.

### 2. 마이페이지와 전체 화면의 호버 디자인 통일

- 마이페이지 메뉴와 버튼마다 호버 효과가 서로 달라 화면의 완성도가 떨어지는 문제를 확인했다.
- 민트, 보라, 핑크 계열의 브랜드 그라데이션으로 공용 호버 스타일을 만들었다.
- 마이페이지뿐 아니라 주문·취소 내역, 배송지 선택, 상품 옵션, 카테고리, 정렬 탭, 수량 버튼, 모달, 푸터와 모바일 네비게이션에도 같은 계열의 호버를 적용했다.
- 삭제 및 주문 취소처럼 위험한 동작은 의미가 구분되도록 기존 빨간색 호버를 유지했다.

### 3. 호버 디자인의 세부 오류 수정

- 둥근 카드 안의 링크에 호버했을 때 배경이 사각형으로 보이는 문제가 있었다.
- 부모 카드에 `overflow-hidden`을 적용해 그라데이션이 기존 라운드 영역 밖으로 나오지 않게 수정했다.
- 호버 시 요소가 위로 1px 움직이면서 카드 아래에 흰 틈이 생기는 문제를 발견했다.
- 일반 메뉴 호버에서는 이동 효과를 제거하고 아이콘 버튼에만 이동 효과를 유지했다.
- 바깥쪽 그림자가 카드 아래에 잔상처럼 보이는 문제도 있어 일반 메뉴 호버에서는 바깥 그림자를 제거했다.

### 4. 주문·취소 내역 화면 수정

- 주문 데이터가 생성된 뒤 나타나는 주문 카드에도 공용 호버를 적용했다.
- 선택된 첫 번째 주문 상태 탭에서 `전체` 글자가 보이지 않고 숫자만 나타나는 문제를 확인했다.
- 전역 링크 색상이 선택 탭의 글자색을 덮어쓰고 있었기 때문에 선택된 탭 라벨을 자식 요소에서 흰색으로 고정했다.
- 수정 후 `전체 1`이 정상적으로 표시되는 것을 화면에서 확인했다.

### 5. 메인 화면 개선

- 아티스트 배너 이미지에 포함된 임시 문구가 그대로 노출되는 문제를 확인했다.
- 메인 아티스트 패널에서는 해당 이미지를 사용하지 않고 아티스트 테마 색상의 밝은 그라데이션을 사용하도록 수정했다.
- 패널 높이를 줄이고 로딩 스켈레톤 크기도 동일하게 맞췄다.
- 중복되는 `새로 나온 굿즈` 영역 대신 사용자가 최근에 확인한 상품을 보여주는 `최근 본 상품` 영역을 추가했다.

### 6. 최근 본 상품 기능 구현 및 리뷰 반영

- 상품 상세페이지를 방문하면 브라우저의 `localStorage`에 최근 본 상품을 기록하도록 구현했다.
- 같은 상품을 다시 보면 중복으로 추가하지 않고 가장 앞으로 이동하도록 했다.
- 메인 화면에는 최근 본 상품을 최대 4개 표시하고, 기록이 없으면 영역 전체를 숨기도록 했다.
- 처음에는 상세 상품 객체 전체를 저장했지만, PR 리뷰를 통해 불필요한 설명, 옵션, 재고 데이터까지 저장되는 문제를 알게 되었다.
- 상품 카드에 필요한 ID, 상품명, 가격, 상태, 대표 이미지, 아티스트, 카테고리 정보만 골라서 저장하도록 수정했다.
- Safari 개인정보 보호 모드나 저장 공간 부족 상황에서도 상세페이지가 깨지지 않도록 `localStorage.setItem`을 `try/catch`로 감쌌다.
- PC 화면에서 8열을 사용해 오른쪽 절반이 비어 보이던 문제를 4열 구성으로 수정했다.

### 7. Git 및 PR 작업

- 작업 전에 `develop`의 최신 내용을 가져와 `dev/jina` 브랜치에 반영했다.
- 충돌 여부를 확인한 뒤 커밋하고 원격 브랜치에 푸시했다.
- 기존 PR이 이미 머지된 상태라는 사실을 뒤늦게 확인해 남은 변경 사항으로 새 PR #31을 생성했다.
- 리뷰어에게 검토를 요청하고, 수정 요청을 확인해 안전성 및 UI 문제를 보완한 뒤 다시 푸시했다.
- 린트와 TypeScript 검사를 반복하여 오류가 없는 상태를 유지했다.

## 발생한 문제와 재시도 과정

### 기존 PR에 변경 사항이 계속 추가된다고 잘못 판단한 문제

처음에는 이미 생성한 PR #25에 이후 커밋도 자동으로 포함될 것이라고 생각했다. 하지만 PR #25는 장바구니 작업까지만 포함된 상태로 이미 머지되어 있었다. 이후 `dev/jina`에 푸시한 변경은 닫힌 PR에 추가되지 않았다.

GitHub에서 PR 상태를 다시 확인하고 `develop`과 `dev/jina`를 비교해 새 PR #31을 생성했다. 이 경험을 통해 원격 브랜치에 푸시하는 것과 PR이 열려 있는지는 별개의 상태라는 점을 다시 확인했다.

### 호버 효과를 한 번에 통일하면서 생긴 시각적 문제

처음에는 공용 CSS 클래스 하나로 색상, 그림자, 이동 효과를 함께 적용했다. 색상은 통일되었지만 둥근 카드가 사각형처럼 보이거나 카드 아래에 흰 틈과 그림자가 남는 문제가 발생했다.

문제를 한 번에 추측해서 수정하지 않고 다음과 같이 나누어 확인했다.

1. 부모 카드가 자식 배경을 잘라주지 않는 문제를 확인하고 `overflow-hidden`을 적용했다.
2. `translateY(-1px)` 때문에 아래쪽이 비는 것을 확인하고 일반 메뉴에서는 이동 효과를 제거했다.
3. 바깥쪽 `box-shadow`가 잔상처럼 보이는 것을 확인하고 메뉴 호버에서는 안쪽 테두리만 유지했다.
4. 아이콘처럼 이동 효과가 어울리는 요소에는 기존 애니메이션을 유지했다.

이 과정을 통해 디자인 통일은 단순히 같은 색을 적용하는 작업이 아니라 기존 크기, 라운드, 그림자, 상태 의미까지 함께 보존해야 한다는 점을 배웠다.

### 리뷰를 통해 발견한 저장 방식의 문제

최근 본 상품 기능은 로컬에서 정상 동작했지만, 리뷰 과정에서 저장 공간과 예외 상황을 충분히 고려하지 않았다는 사실을 알게 되었다. 정상적인 환경에서 동작하는 것만으로는 완성된 기능이라고 보기 어렵다.

리뷰 의견에 따라 저장 데이터를 최소화하고 쓰기 실패를 예외 처리했다. 화면 구현뿐 아니라 브라우저 환경 차이와 데이터의 수명까지 고려해야 한다는 점을 배웠다.

## 오늘의 위기 상황과 대응

가장 큰 위기 상황은 4명으로 구성된 팀에서 2명이 개인 사정으로 빠져, 남은 2명이 당일 작업을 이어가야 했던 것이다. 인원이 절반으로 줄어들면서 각자의 담당 범위를 넘어 다른 팀원의 화면과 기능까지 확인해야 했다.

우리는 모든 작업을 한꺼번에 해결하려 하지 않고 다음 기준으로 우선순위를 정했다.

1. 다른 팀원의 작업을 막는 기능 오류를 먼저 해결했다.
2. 사용자가 바로 확인할 수 있는 화면 오류를 수정했다.
3. 공용 컴포넌트와 전역 스타일을 활용해 반복 작업을 줄였다.
4. 변경할 때마다 로컬 화면, 린트, 타입 검사를 확인했다.
5. PR 리뷰를 통해 놓친 부분을 보완했다.

인원이 부족한 상황에서도 두 사람이 역할을 나누고 계속 소통했기 때문에 핵심 기능을 중단하지 않고 마무리할 수 있었다. 오늘은 단순히 많은 작업을 처리한 날이 아니라, 예상치 못한 결원 상황에서 협업 방식과 우선순위 판단의 중요성을 경험한 날이었다.

## 배운 점

- 원격 브랜치에 푸시했다고 해서 이미 닫힌 PR이 다시 갱신되는 것은 아니다.
- PR의 대상 브랜치, 상태, 리뷰 여부를 직접 확인해야 한다.
- 공용 스타일 변경은 한 화면뿐 아니라 모든 사용처에 영향을 줄 수 있다.
- 호버 색상을 통일할 때도 라운드, 그림자, 이동, 비활성 상태와 위험 동작의 의미를 함께 고려해야 한다.
- `localStorage`도 쓰기 실패가 발생할 수 있으므로 읽기와 쓰기 모두 예외 처리가 필요하다.
- 상세 데이터 전체를 저장하기보다 화면에 필요한 최소 데이터만 저장하는 편이 안전하다.
- 팀원이 부족할수록 해야 할 일을 모두 펼치기보다 서비스 이용을 막는 문제부터 해결해야 한다.
- 작업 결과를 자주 공유하면 두 명만 남은 상황에서도 중복 작업과 방향 차이를 줄일 수 있다.

## 다음 작업에서 개선할 점

- 작업 시작 전에 PR이 열려 있는지와 대상 브랜치를 먼저 확인한다.
- 공용 CSS를 수정하기 전 사용되는 모든 화면을 검색해 영향 범위를 정리한다.
- 정상 동작뿐 아니라 저장 실패, 빈 데이터, 비활성 상태와 모바일 화면도 함께 확인한다.
- 화면 수정 후에는 기본 상태와 호버 상태를 모두 캡처하여 비교한다.
- 담당자가 없는 날을 대비해 주요 컴포넌트의 구조와 데이터 흐름을 팀원 모두가 이해할 수 있도록 작업 기록을 남긴다.
- 이미지 작업은 규격, 폴더 경로, 파일명을 먼저 확정한 뒤 제작하여 재작업을 줄인다.
