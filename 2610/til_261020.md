## 오늘 학습한 내용

오늘은 HTML과 CSS로 만든 회원관리 페이지의 레이아웃을 확장하고, 다양한 화면 크기에 대응하도록 반응형 웹을 적용한 뒤 JavaScript 기초까지 학습했다. 하루에 Flexbox, Grid, Media Query, 변수, 조건문, 반복문을 연속해서 다루다 보니 단순히 코드를 따라 입력하는 것만으로는 현재 무엇을 배우고 있는지 놓치기 쉬웠다.

그래서 수업 화면과 내 프로젝트의 폴더 구조를 계속 비교하고, 브라우저와 Console에서 결과를 직접 확인하는 방식으로 진행했다. 특히 교수님 화면과 파일 위치가 다르면 코드가 맞아도 실행 주소가 달라질 수 있다는 점을 경험했다.

오늘 학습 흐름은 다음과 같았다.

```text
Flexbox로 한 방향 정렬
        ↓
Grid로 행과 열 구성
        ↓
Media Query로 화면 크기 대응
        ↓
JavaScript로 데이터 저장과 판단
        ↓
입력값 검증과 계산기 구현
        ↓
테스트 코드로 동작 확인
```

## 1. Flexbox와 Grid를 함께 사용한 회원관리 화면

Chapter 06에서는 Flexbox와 Grid의 역할을 구분해 회원관리 페이지를 만들었다.

- Header의 제목과 메뉴: Flexbox
- 검색창과 버튼이 있는 Toolbar: Flexbox
- 회원 카드 목록: CSS Grid
- 카드 내부 버튼: Flexbox

처음에는 `justify-content`는 가로 정렬, `align-items`는 세로 정렬이라고 외우려고 했다. 하지만 `flex-direction`이 `column`으로 변경되면 Main Axis와 Cross Axis도 함께 바뀐다는 점 때문에 이런 방식으로 외우면 안 된다는 것을 알게 됐다.

```css
.site-header {
    display: flex;
    justify-content: space-between;
    align-items: center;
}
```

위 코드에서 `justify-content`는 무조건 가로를 의미하는 것이 아니라 Main Axis를 기준으로 정렬한다. 기본값인 `flex-direction: row`에서 Main Axis가 가로이기 때문에 가로 정렬처럼 보이는 것이다.

회원 카드 영역은 다음과 같이 Grid를 사용했다.

```css
.member-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 20px;
}
```

`repeat(3, 1fr)`는 남은 공간을 동일한 비율의 세 열로 나눈다는 뜻이다. 카드마다 너비를 직접 계산하지 않아도 부모 Grid가 전체 배치를 처리한다는 점이 편리했다.

### 해보고 느낀 점

Flexbox와 Grid 중 하나만 골라 페이지 전체를 만드는 것이 아니라, 화면의 작은 영역마다 목적에 맞는 도구를 선택하는 것이 중요했다. Header와 버튼처럼 한 방향 정렬은 Flexbox가 자연스러웠고, 여러 카드를 행과 열로 배치할 때는 Grid가 훨씬 단순했다.

## 2. 가장 먼저 막힌 부분: 교수님과 다른 파일 구조

코드 자체보다 파일 구조를 맞추는 과정에서 여러 번 혼란이 생겼다. 처음에는 `chapter06` 바로 아래에 `index.html`과 `style.css`를 만들었지만, 교수님 화면은 다음처럼 실습 목적에 따라 폴더가 나뉘어 있었다.

```text
chapter06/
├─ CSSGrid/
├─ flexbox/
└─ member/
   ├─ index.html
   └─ style.css
```

처음 만든 파일을 그대로 둔 채 새 파일을 추가하면 Live Server 주소와 교수님이 설명하는 경로가 달라질 수 있었다. 이를 해결하기 위해 Flexbox 실습 파일은 `flexbox` 폴더로 옮기고, 회원관리 실습은 `member` 폴더에 따로 구성했다.

이후 Chapter 07에서도 같은 문제가 있었다. 처음에는 Chapter 07 루트에 반응형 파일을 만들었지만 교수님은 `viewport`, `scale`, `media`, `breakpoint`, `mobilefirst`, `responsible`, `member`처럼 개념별 폴더를 사용했다.

이 경험을 통해 코드를 작성하기 전에 다음을 먼저 확인하는 습관이 필요하다고 느꼈다.

1. 현재 작업 중인 Chapter가 맞는가?
2. 교수님이 실행한 파일의 정확한 경로는 무엇인가?
3. HTML이 연결하는 CSS와 JavaScript 파일명이 일치하는가?
4. Live Server의 URL이 내가 수정한 파일을 가리키는가?

## 3. Go Live가 사라진 것처럼 보였던 문제

VS Code 오른쪽 아래에서 `Go Live`가 보이지 않아 Live Server가 사라졌다고 생각했다. 하지만 실제로는 서버가 이미 실행 중이어서 표시가 다음처럼 바뀐 상태였다.

```text
Go Live    → 서버가 꺼진 상태
Port: 5500 → 서버가 실행 중인 상태
```

처음에는 확장 프로그램이 삭제됐거나 비활성화됐다고 생각했지만, `Port: 5500`이 보이면 정상 실행 중이라는 것을 확인했다. 실행 주소도 폴더 구조에 맞게 직접 확인했다.

```text
http://127.0.0.1:5500/practice/phase01/chapter07/member/index.html
```

앞으로는 버튼 이름만 찾지 않고 상태 표시와 현재 URL을 먼저 확인해야겠다.

## 4. 반응형 웹과 Mobile First

Chapter 07에서는 하나의 HTML이 모바일, 태블릿, 데스크톱에서 자연스럽게 보이도록 CSS를 확장했다.

먼저 모바일 화면을 기본값으로 작성했다.

```css
.member-grid {
    display: grid;
    grid-template-columns: 1fr;
    gap: 16px;
}
```

화면이 넓어지면 Media Query로 열 수를 늘렸다.

```css
@media (min-width: 768px) {
    .member-grid {
        grid-template-columns: repeat(2, 1fr);
    }
}

@media (min-width: 1024px) {
    .member-grid {
        grid-template-columns: repeat(3, 1fr);
    }
}
```

최종 동작은 다음과 같다.

| 화면 | 카드 배치 |
|---|---|
| 768px 미만 | 1열 |
| 768px 이상 | 2열 |
| 1024px 이상 | 3열 |

### 어려웠던 부분

처음에는 768px과 1024px을 반드시 외워야 하는 숫자로 생각했다. 하지만 Breakpoint는 정답이 고정된 값이 아니라 콘텐츠가 불편해지기 시작하는 지점이라는 설명을 듣고 이해가 쉬워졌다.

또한 데스크톱 화면을 먼저 만든 다음 계속 크기를 줄이려고 하면 CSS를 덮어쓰는 규칙이 복잡해졌다. 모바일 1열을 기본값으로 두고 화면이 커질수록 2열과 3열로 확장하니 코드의 흐름이 더 분명했다.

Header도 모바일에서는 세로, 넓은 화면에서는 가로가 되도록 구성했다.

```css
.header {
    display: flex;
    flex-direction: column;
}

@media (min-width: 768px) {
    .header {
        flex-direction: row;
        justify-content: space-between;
        align-items: center;
    }
}
```

## 5. 모바일 화면에서 요소가 밖으로 나가는 문제와 해결

검색창이나 긴 이메일 문자열이 카드 너비를 밀어내면 가로 스크롤이 생길 수 있었다. 이를 막기 위해 입력 요소에는 `max-width`와 `width`를 적용했다.

```css
input,
select,
textarea,
button {
    max-width: 100%;
}

input,
select,
textarea {
    width: 100%;
    box-sizing: border-box;
}
```

Grid 안의 카드에는 `min-width: 0`을 적용하고 긴 문자열에는 줄바꿈이 가능하도록 했다.

```css
.member-card {
    min-width: 0;
}

.member-card p {
    overflow-wrap: anywhere;
}
```

단순히 화면이 좁아졌을 때 열 수만 바꾸는 것이 반응형 웹의 전부가 아니었다. 입력창, 긴 텍스트, 버튼, 이미지가 부모 영역을 넘어가지 않는지도 함께 확인해야 했다.

## 6. JavaScript 변수, 조건문, 반복문

Chapter 08에서는 HTML과 CSS에서 벗어나 JavaScript가 데이터를 처리하는 흐름을 학습했다.

```text
변수에 값 저장
    ↓
자료형 확인 및 변환
    ↓
연산자로 비교
    ↓
조건문으로 판단
    ↓
반복문으로 여러 데이터 처리
```

`const`는 다시 다른 값을 할당하지 않을 때 사용하고, 실제로 값이 변경돼야 할 때만 `let`을 사용했다.

```js
const memberName = '홍길동';
let memberCount = 3;

memberCount = 4;
```

회원의 나이와 활성 상태를 함께 판단할 때는 논리 연산자 `&&`를 사용했다.

```js
if (age >= 20 && active) {
    console.log(`${memberName}님은 이용 가능한 성인 회원입니다.`);
} else {
    console.log(`${memberName}님은 이용 조건을 확인해야 합니다.`);
}
```

여러 회원 이름은 `for...of`로 값 자체를 가져왔고, 번호가 필요할 때는 index를 사용할 수 있는 기본 `for`문을 사용했다.

## 7. 의도적으로 오류를 만들고 Console 읽기

수업에서는 존재하지 않는 변수를 출력해 오류를 확인했다.

```js
console.log(memberEmail);
```

결과는 다음과 같은 `ReferenceError`였다.

```text
ReferenceError: memberEmail is not defined
```

예전에는 빨간 오류가 보이면 바로 코드를 다시 복사하려고 했다. 이번에는 오류 종류, 파일명, 줄 번호를 먼저 읽었다. `memberEmail`이라는 변수가 선언되지 않았다는 뜻을 확인하니 원인이 명확했다.

오류를 없애는 것만 목표로 하지 않고 오류 메시지가 무엇을 알려주는지 읽는 연습이 필요하다고 느꼈다.

## 8. 사칙연산 계산기에서 잘 안 됐던 부분

두 개의 입력창, 연산자 선택창, 계산 버튼을 가진 사칙연산 계산기를 만들었다. 가장 중요한 문제는 입력창에서 가져온 값이 항상 문자열이라는 점이었다.

예를 들어 입력값 `10`과 `5`를 그대로 더하면 숫자 15가 아니라 문자열 `105`가 될 수 있다. 이를 해결하기 위해 `Number()`로 변환했다.

```js
const firstNumber = Number(firstValue);
const secondNumber = Number(secondValue);
```

문자열을 숫자로 바꾸는 것만으로는 부족했다. 빈 값과 숫자가 아닌 입력도 구분해야 했다.

```js
if (firstValue === '' || secondValue === '') {
    alert('두 숫자를 모두 입력해 주세요.');
    return;
}

if (Number.isNaN(firstNumber) || Number.isNaN(secondNumber)) {
    alert('숫자만 입력해 주세요.');
    return;
}
```

나눗셈에서는 두 번째 숫자가 0인지 별도로 확인했다.

```js
if (secondNumber === 0) {
    throw new Error('0으로 나눌 수 없습니다.');
}
```

### 해결 과정에서 배운 점

입력 검증 순서가 중요했다.

1. 공백을 제거한다.
2. 비어 있는지 확인한다.
3. 숫자로 변환한다.
4. 숫자 변환에 성공했는지 확인한다.
5. 연산별 예외 조건을 확인한다.
6. 계산을 실행한다.

이 순서로 나누니 한꺼번에 복잡한 조건문을 작성하는 것보다 원인을 찾기 쉬웠다.

## 9. 테스트 코드를 작성하며 느낀 점

처음에는 계산기 화면에서 숫자를 직접 입력하고 버튼을 누르는 것만 테스트라고 생각했다. 하지만 매번 같은 값을 반복 입력하는 방식은 빠뜨리는 경우가 생길 수 있었다.

계산 부분을 `calculate()` 함수로 분리하고 별도의 `test.js`에서 예상 결과와 실제 결과를 비교했다.

```js
test('10 + 5 = 15', calculate(10, 5, '+'), 15);
test('10 - 5 = 5', calculate(10, 5, '-'), 5);
test('10 * 5 = 50', calculate(10, 5, '*'), 50);
test('10 / 5 = 2', calculate(10, 5, '/'), 2);
```

정상적인 양수만 검사하지 않고 음수, 소수, 0으로 나누기도 확인했다. 기능을 구현한 뒤 “되는 것 같다”라고 끝내는 것이 아니라 어떤 입력을 확인했는지 기록하는 것이 중요했다.

## 10. 회원 5명 판별 과제

과제에서는 회원 이름과 나이를 배열에 저장하고 반복문으로 한 명씩 처리했다. 각 회원이 20세 이상이면 성인, 그렇지 않으면 미성년으로 출력했다.

```text
1. 홍길동 - 25세 - 성인
2. 김영희 - 19세 - 미성년
3. 이철수 - 32세 - 성인
4. 박민지 - 17세 - 미성년
5. 최준호 - 21세 - 성인
전체 회원 수: 5
```

반복문은 모든 회원에게 같은 처리를 적용하고, 조건문은 현재 회원의 상태를 판단한다. 두 문법의 역할을 과제 안에서 함께 사용해 보니 차이가 더 명확해졌다.

## 11. Git과 GitHub에서 겪은 문제

VS Code Source Control에서 현재 폴더가 Git 저장소가 아니라는 안내가 나왔다. 또한 같은 이름의 GitHub Repository가 이미 존재해 새 저장소를 만들 수 없었다.

새 Repository를 다시 만드는 대신 기존 `pang789789/fullstack-web-course` 저장소의 내용을 먼저 가져오고, 기존 파일을 보존한 상태에서 Chapter 파일만 추가했다.

```text
원격 저장소 확인
    ↓
기존 main 브랜치 가져오기
    ↓
변경 파일만 stage
    ↓
diff와 문법 검사
    ↓
commit
    ↓
push
    ↓
GitHub에서 파일 직접 확인
```

무조건 `git init`과 `push`부터 하는 것보다 원격 저장소에 무엇이 있는지 확인하는 과정이 먼저라는 점을 배웠다.

| 교수님 URL과 결과가 다름 | CSS 코드 오류 | 실행한 폴더와 파일 경로가 다름 | Explorer 구조와 브라우저 URL 비교 |
| 모바일에서 레이아웃이 답답함 | 카드 디자인 문제 | 데스크톱 3열이 기본값 | 모바일 1열을 기본으로 변경 |
| 숫자 덧셈 결과가 이상함 | 연산자 조건문 오류 | input 값이 문자열 | `Number()`로 변환 |
| 잘못된 입력도 계산됨 | 브라우저 문제 | 입력값 검증 누락 | 빈 값과 `Number.isNaN()` 검사 |
| 나눗셈 결과가 비정상 | JavaScript 오류 | 0으로 나누기 허용 | 계산 전 `secondNumber === 0` 검사 |
| Source Control에서 저장소가 없다고 표시 | GitHub 연결 오류 | 로컬 폴더에 `.git`이 없음 | 기존 원격 저장소를 확인하고 연결 |

## 오늘 배운 내용을 내 말로 정리

Flexbox는 요소를 한 방향으로 배치하고 정렬할 때 사용하고, Grid는 여러 행과 열로 구성된 목록을 배치할 때 유용하다. 반응형 웹은 별도의 모바일 HTML을 만드는 것이 아니라 하나의 HTML에 화면 크기별 CSS 규칙을 적용하는 방식이다.

JavaScript는 화면에 있는 데이터를 저장하고 비교하고 반복 처리한다. 조건문은 현재 상황에 따라 실행할 코드를 선택하고, 반복문은 여러 데이터에 같은 처리를 적용한다. 사용자가 입력한 값은 믿고 바로 계산하면 안 되며, 비어 있는지와 올바른 자료형인지 먼저 확인해야 한다.

오늘 가장 크게 느낀 점은 코드를 작성하는 것만큼 실행 위치와 결과를 검증하는 과정이 중요하다는 것이다. 앞으로는 교수님 코드를 그대로 복사하는 데서 끝내지 않고, 파일 경로·브라우저 URL·Console·DevTools·Git 상태를 함께 확인하는 습관을 들여야겠다.
