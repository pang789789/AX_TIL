# 2026-10-12 프로젝트 3일차 작업 기록 및 회고

## 오늘의 상황

오늘은 상품 이미지와 상세 안내 이미지의 품질을 다시 점검하면서, DAYLOG 페이지의 정보와 캐릭터 설정을 실제 전달 자료에 맞게 정리했다. 동시에 변경된 KANT·MOA 로고를 사이트 전체에 적용하고, 기존의 화려한 호버 색상을 새 로고의 검정·흰색 중심 분위기에 맞게 통일했다.

작업 범위가 이미지 제작, 상품 데이터, 프로필 정보, 공용 UI, 문서 정리까지 넓었기 때문에 단순히 한 화면만 고치는 방식으로는 누락이 생기기 쉬웠다. 로그인 전후, 상품 목록과 상세, 아티스트 페이지 등 로고와 호버가 나타나는 위치를 나누어 확인하고, 변경 사항을 한 커밋으로 정리했다.

## 발생한 문제와 해결 과정

### 이미지 크기만 줄이면 해결된다고 판단한 문제

처음에는 큰 이미지를 카드 크기에 맞게 축소하면 된다고 생각했지만, 실제로는 상품이 지나치게 작아지고 넓은 회색 공백만 남았다. 상품마다 원본 이미지의 여백과 구성이 다르기 때문에 같은 축소율을 일괄 적용하면 결과가 달라졌다.

대표 이미지와 상세 이미지를 구분하고, 상품이 원본에서 차지하는 비율을 먼저 확인한 뒤 `object-fit`, 내부 여백, 배경색을 결정해야 한다는 점을 배웠다. 특히 이미 배경이 포함된 상품 이미지는 다시 누끼 이미지처럼 취급하지 않아야 한다.

### 상세 이미지를 한 화면에 축소하면서 가독성이 떨어진 문제

판매 공지와 환불 안내처럼 글자가 많은 이미지를 한 장에 맞추려고 축소하자 글자가 작아지고, 일부 문장이 박스 밖으로 튀어나왔다. 상세 이미지는 카드 썸네일이 아니라 사용자가 세로로 읽는 문서이므로, 원래 크기를 유지하고 섹션별 이미지를 순서대로 배치해 스크롤하도록 구성하는 편이 적절했다.

### 로고만 교체했을 때 사이트 분위기가 어긋난 문제

새 로고는 검정과 흰색 중심인데 기존 호버는 파스텔 그라데이션이라 서로 다른 서비스처럼 보였다. 로고 자산만 바꾸는 것으로는 브랜드 교체가 끝나지 않았다.

공용 CSS와 버튼 컴포넌트를 먼저 정리하고, 로그인 전후에 나타나는 링크와 버튼을 모두 검색해 남은 색상을 교체했다. 이를 통해 브랜드 변경은 로고, 색상, 상호작용 상태, 탐색 요소를 함께 맞추는 작업이라는 점을 알게 되었다.

### 공용 레이아웃 수정으로 뒤로가기 동선이 사라진 문제

아티스트와 상품 화면의 헤더 구성을 바꾸는 과정에서 일부 페이지는 뒤로 갈 수 있는 수단이 사라졌다. 화면이 깔끔해지는 것보다 사용자가 현재 위치에서 빠져나올 수 있는 탐색 수단을 보존하는 것이 우선이었다.

별도의 `BackButton`을 추가하고 페이지별 표시 조건을 확인했다. 레이아웃을 단순화할 때는 시각적 요소뿐 아니라 내비게이션 역할도 함께 점검해야 한다.

### 화면과 데이터 자료의 명칭이 달랐던 문제

프로필 카드의 마스코트 이름과 실제 인형 이미지의 이름이 달랐고, 멤버 출생일도 전달 자료와 코드가 일치하지 않았다. 텍스트만 보고 임의로 고치면 다른 멤버의 설정과 다시 충돌할 수 있었다.

이미지 자료, 상품 파일, DB 마이그레이션, 서비스 데이터를 함께 비교해 하나의 기준으로 맞추었다. 콘텐츠 중심 서비스에서는 UI 구현뿐 아니라 원본 자료의 정확성 검증도 개발 과정의 일부라는 점을 배웠다.

## 배운 점

- 이미지 작업은 파일을 넣는 것으로 끝나지 않고 원본 비율, 배경 포함 여부, 화면 용도까지 확인해야 한다.
- 대표 이미지와 상세 이미지는 목적이 다르므로 같은 크기 정책을 사용하면 안 된다.
- 글자가 많은 상세 안내는 축소보다 섹션 분리와 세로 스크롤이 가독성에 유리하다.
- 브랜드 로고가 바뀌면 호버, 버튼, 링크, 헤더와 내비게이션까지 함께 점검해야 한다.
- 공용 CSS 수정은 빠르지만 영향 범위가 넓으므로 로그인 전후와 여러 페이지 상태를 모두 확인해야 한다.
- 데이터 수정은 화면 텍스트만 고치지 말고 DB 마이그레이션과 서비스 fallback 데이터까지 일치시켜야 한다.
- 참고 사이트의 수치를 그대로 적용해도 우리 이미지와 콘텐츠에 맞지 않을 수 있으며, 실제 화면 검증 후 되돌릴 판단이 필요하다.
- Git 커밋을 작게 나누면 어떤 조정이 문제를 만들었는지 찾고 되돌리기 쉽다.
- 팀 문서는 결과만 적기보다 막힌 점, 시도, 해결 방법, 산출물 링크를 함께 남겨야 이후 작업 근거가 된다.

## 다음 작업에서 개선할 점

- 이미지 작업 전에 상품별 대표·상세 파일 목록과 권장 규격을 표로 정리한다.
- 원본에 배경이 있는 이미지와 투명 배경 이미지를 구분해 서로 다른 표시 규칙을 적용한다.
- 상세 이미지 파일명에 표시 순서를 포함하고 코드 배열도 같은 순서로 관리한다.
- 공용 스타일을 바꾸기 전에 사용처를 검색해 로그인 전후 체크리스트를 만든다.
- 프로필, 마스코트, 생일처럼 설정 정확성이 중요한 정보는 원본 자료를 기준으로 검수한다.
- DB와 정적 fallback 데이터를 함께 바꿔야 하는 작업은 하나의 체크리스트로 묶는다.
- 커밋 전에 데스크톱·모바일, 기본·호버, 로그인·로그아웃 상태를 모두 확인한다.
- Git에 남지 않는 이미지 제작과 문서 작업도 당일 TIL과 개인 작업 일지에 바로 기록한다.

## 한 줄 회고

오늘은 단순히 이미지를 교체하거나 색을 바꾼 날이 아니라, 원본 자료·데이터·공용 UI·브랜드 경험을 하나의 기준으로 맞추는 과정에서 검수와 기록의 중요성을 배운 하루였다.
