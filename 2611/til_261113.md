## 1. 미니 팝업 스토어 실습 진도 정리

```text
└─ member-next-app/
```

기존 작업을 바로 삭제하면 이전 실습 내용을 잃을 수 있기 때문에, 우선 기존 `mini-popup-store-app`은 보존하고 교수님 공유본의 `backend`와 `member-next-app`을 추가했다. 앞으로는 공식 경로인 `member-next-app`을 기준으로 수업을 따라가기로 했다.

이번 과정을 통해 **새 자료를 받았다고 기존 폴더를 바로 지우는 것보다, 먼저 구조와 차이를 비교하고 기준 폴더를 결정하는 것이 안전하다**는 점을 배웠다.

## 2. Product와 CartItem의 역할

미니 팝업 스토어에서는 상품 자체의 정보와 장바구니에 담긴 정보를 구분해야 했다.

```typescript
type Product = {
  id: number;
  name: string;
  price: number;
  category: string;
  stock: number;
};
```

`Product`는 상품의 원본 정보를 표현한다. 반면 `CartItem`은 상품과 장바구니 수량을 함께 표현한다.

```typescript
type CartItem = {
  product: Product;
  quantity: number;
};
```

처음에는 상품 객체에 수량을 바로 추가해도 될 것 같았지만, 상품 재고와 내가 장바구니에 담은 수량은 의미가 다르다. 두 값을 분리하니 상품 데이터 자체를 변경하지 않고 장바구니 상태만 관리할 수 있었다.

샘플 상품 6개를 배열로 만들고 `map()`으로 `ProductCard`를 반복 렌더링했다. React에서 목록을 표시할 때는 각 항목을 구별할 수 있도록 `key`에 상품 ID를 사용했다.

## 3. Playwright 테스트 경로가 서로 달랐던 문제

수업 화면에서는 다음 명령을 실행하는 모습이 보였다.

```powershell
npx playwright test e2e/products.spec.ts --workers=1
```

같은 명령을 현재 공유본에서 실행했지만 다음 오류가 발생했다.

```text
Error: No tests found
```

처음에는 Playwright 설치가 잘못됐다고 생각했지만, 실제 원인은 패키지가 아니라 **테스트 파일 경로의 차이**였다.

현재 공유본에는 다음 파일만 있었다.

```text
tests/mini-popup-store.spec.ts
```

반면 참고 화면에는 `e2e/products.spec.ts` 또는 `e2e/popup-store.spec.ts`처럼 다른 이름과 폴더가 사용되고 있었다. 같은 STEP을 진행해도 교수님 자료, 학생 화면, 배포 시점에 따라 파일 구조가 달라질 수 있었다.

이 문제를 해결할 때는 명령을 계속 반복하기보다 먼저 실제 파일을 찾아보는 것이 효과적이었다.

```text
명령 실패
→ 오류 메시지 확인
→ 현재 프로젝트에서 *.spec.ts 검색
→ 실제 파일 경로 확인
→ 그 경로로 명령 수정
```

또한 다른 학생 화면에서 `3 passed`, 비디오 녹화, HTML 리포트가 보였지만 그것을 교수님의 확정 코드로 오해하지 않도록 주의했다. 참고 화면은 참고만 하고, 실제 교수님 안내나 공유 파일을 기준으로 적용해야 한다.

## 4. 새로운 AI Agent Engineering 과정 시작

오후에는 AI Agent Engineering 과정의 전체 로드맵을 살펴봤다. 총 15강 동안 하나의 **My AI Assistant** 프로젝트를 계속 발전시키는 방식이었다.

주요 학습 흐름은 다음과 같다.

```text
Python 질문 입력과 Mock 응답
→ OpenAI / Gemini 모델 연결
→ Prompt와 Context 설계
→ 문서 검색과 RAG
```

RAG, Embedding, Tool Calling, MCP 같은 용어가 한꺼번에 나와 처음에는 복잡하게 느껴졌다. 하지만 첫 강의에서는 실제 모델을 바로 연결하는 것이 아니라 Mock 응답으로 프로그램의 입력·처리·출력 구조부터 확인한다는 점이 부담을 줄여 주었다.

## 5. fork와 clone의 차이 이해하기

처음에는 저장소를 `fork`해야 한다고 이해했지만, 실제 강의 화면과 교안에 나온 명령은 다음과 같은 `clone`이었다.

```powershell
git clone https://github.com/GilbertMoon/ai-agent-practice.git
```

두 작업은 비슷해 보이지만 목적이 다르다.

| 구분 | 의미 |
|---|---|
| fork | GitHub 내 계정에 원본 저장소의 사본을 만든다 |
| clone | 원격 저장소를 내 컴퓨터로 내려받는다 |

이번 수업에서는 우선 교수님의 공개 저장소를 로컬에 내려받아 실행하는 것이 목적이므로 fork 없이 clone만 진행했다.

최종 프로젝트 경로는 다음과 같다.

```text
C:\dev\ai-agent-practice
```

실제 실습 폴더는 다음 위치다.

```text
C:\dev\ai-agent-practice\practice\my-ai-assistant
```

터미널 명령은 저장소 루트와 실습 폴더 중 어디에서 실행하는지에 따라 결과가 달라진다. 화면에서 처음 `Set-Location` 경로를 잘못 입력했을 때 폴더를 찾을 수 없다는 오류가 발생했고, 현재 위치를 기준으로 올바른 상대 경로를 사용하자 해결됐다.

## 6. Python 3.12 가상환경 준비

교안의 권장 버전은 Python 3.12였다. 처음 단순히 다음 명령으로 가상환경을 만들었을 때는 시스템 기본 Python인 3.13이 선택됐다.

```powershell
python -m venv .venv
```

코드가 당장 실행될 수는 있었지만 강의 환경과 버전이 다르면 이후 패키지 호환 문제를 만날 수 있다. 설치된 Python 목록을 확인한 뒤 3.12를 명시해 가상환경을 다시 만들었다.

```powershell
py -3.12 -m venv .venv
```

최종 확인 결과는 다음과 같았다.

```text
Python 3.12.10
```

가상환경에는 `requirements.txt`의 패키지를 설치했다.

```text
openai
google-genai
chromadb
```

이 과정에서 깨달은 점은 터미널 앞에 `(.venv)`가 표시되는 것만 확인해서는 부족하다는 것이다. 가상환경이 활성화되어 있어도 어떤 Python 버전으로 만들어졌는지는 별도로 `python --version`으로 확인해야 한다.

## 7. 첫 Mock AI 비서 실행

API Key 없이 첫 프로그램을 실행했다.

```powershell
python main.py "안녕하세요"
```

프로그램은 질문을 입력받고 Mock 응답을 반환했다.

```text
[mode=mock; model=mock-fixture]
[MOCK 예시] 질문을 받았습니다: 안녕하세요
실제 OpenAI API 응답이 아닙니다.
```

Mock은 실제 AI 모델을 호출하지 않고 미리 정해진 응답으로 프로그램 흐름을 확인하는 방법이다. 따라서 API Key가 없어도 실행할 수 있고 별도의 모델 사용 요금도 발생하지 않는다.

Mock 결과에서 중요한 것은 답변의 지능이 아니라 다음 흐름이 정상적으로 이어지는지 확인하는 것이다.

```text
명령행 인자 입력
→ 질문 문자열 검증
→ Mock Client 선택
→ 응답 생성
→ 터미널 출력
```

## 8. 자동 테스트 64개 실행

환경 준비가 끝난 뒤 전체 자동 테스트를 실행했다.

```powershell
python -m unittest discover -s tests -v
```

최종 결과는 다음과 같았다.

```text
Ran 64 tests
OK
```

테스트에는 단순 Mock 응답뿐 아니라 빈 질문 처리, 문서 검색, Embedding 검색, Vector Store, Provider 설정과 Failover 관련 검증도 포함되어 있었다. 아직 모든 코드를 배우지는 않았지만, 현재 저장소가 정상 상태인지 먼저 확인하는 기준으로 사용할 수 있었다.

파일이 존재하고 실행 화면이 보인다고 해서 환경 준비가 끝난 것은 아니다. 실제 명령을 실행하고 전체 테스트가 통과하는 것까지 확인해야 한다는 수업 원칙을 다시 체감했다.

## 9. 나만의 AI 비서 목표 작성

`MY_ASSISTANT_GOAL.md` 파일을 만들고 앞으로 구현할 비서의 목표를 정리했다.

내가 만들고 싶은 비서는 **학습 도우미**다.

해결하고 싶은 문제는 다음과 같이 정했다.

- 새로운 주제와 과목의 학습 목표를 정하기 어렵다.
- 학생 수준에 맞는 강의안을 작성하는 데 도움이 필요하다.
- 작성된 강의안의 핵심을 직관적이고 쉽게 설명하는 요약이 필요하다.

사용자가 입력할 대표 질문은 다음과 같다.

```text
이번 주 학습할 내용을 정리해 줘.
```

최종적으로 기대하는 기능은 다음과 같다.

```text
문서 검색
쉬운 설명
이전 대화 기억
실행 결과 검증
```

이 문서는 학생마다 내용이 다른 개인 목표 파일이므로 `.gitignore`에서 제외되는 것도 확인했다.

```gitignore
MY_ASSISTANT_GOAL.md
```

덕분에 개인적인 목표나 실습 아이디어를 원격 저장소에 의도치 않게 올리지 않고 로컬에서 관리할 수 있다.

## 10. 어려웠던 부분과 해결 방법

### 1. 교수님 화면과 공유본의 폴더 구조가 달랐다

화면에는 `react/member-next-app`, `e2e` 폴더가 보였지만 실제 받은 공유본은 `practice/phase03/member-next-app`, `tests` 구조였다.

화면만 보고 폴더를 새로 만들지 않고, ZIP의 실제 구조와 파일을 먼저 확인한 뒤 공식 공유본을 기준으로 정리했다.

### 2. Playwright가 테스트를 찾지 못했다

`e2e/products.spec.ts`가 실제 프로젝트에 없었다. 패키지 오류로 단정하지 않고 `*.spec.ts` 파일을 찾아 실제 경로가 `tests/mini-popup-store.spec.ts`라는 것을 확인했다.

### 3. clone과 fork를 혼동했다

교안의 목적은 GitHub 계정에 사본을 만드는 것이 아니라 공개 저장소를 PC에 내려받아 실행하는 것이었다. 실제 명령을 확인하고 `git clone`만 진행했다.

### 4. 가상환경의 Python 버전이 강의와 달랐다

기본 `python` 명령이 3.13을 가리켜 처음 가상환경도 3.13으로 만들어졌다. 설치된 Python 목록을 확인하고 `py -3.12`를 지정해 3.12.10 환경으로 다시 구성했다.

### 5. 터미널 출력의 한글이 일부 깨져 보였다

자동 실행 결과를 수집하는 화면에서는 인코딩 차이로 한글이 깨져 보였지만, 테스트 결과와 프로그램 동작은 정상적이었다. VS Code 터미널에서는 Mock 한글 응답이 정상 출력되는 것을 확인했다. 출력 깨짐과 프로그램 로직 오류를 구분해야 했다.

## 11. 해보고 느낀 점

오늘은 새로운 기능을 많이 구현하기보다 **수업의 기준이 되는 환경을 정확히 만드는 과정**이 중심이었다. 처음에는 폴더를 복사하고 가상환경을 만드는 일이 단순해 보였지만, 실제로는 경로, Python 버전, 테스트 파일 위치, 공유본 시점이 조금씩 달라 여러 번 확인이 필요했다.

가장 크게 느낀 점은 화면을 그대로 따라 치는 것만으로는 부족하다는 것이다. 같은 명령도 현재 폴더가 다르면 실패하고, 같은 프로젝트 이름이어도 파일 구조가 다르면 테스트를 찾지 못한다. 오류가 발생했을 때는 다음 세 가지를 먼저 확인하는 습관이 중요했다.

```text
1. 나는 지금 어느 폴더에 있는가?
2. 실행하려는 파일이 실제로 존재하는가?
3. 현재 사용 중인 Python과 가상환경 버전은 무엇인가?
```

AI Agent 과정에서는 아직 실제 OpenAI API를 연결하지 않았지만, Mock으로 먼저 프로그램의 골격을 확인하는 방식이 이해에 도움이 됐다. 바로 실제 모델을 연결했다면 코드 오류와 API Key·요금·네트워크 문제를 동시에 구분해야 했을 것이다.

또한 나만의 비서 목표를 글로 먼저 정리해 보니 앞으로 배우는 RAG, Memory, Evaluation 기능이 왜 필요한지 조금 더 구체적으로 연결됐다. 단순히 기술을 모두 넣는 것이 아니라, 학습 자료에서 핵심을 찾고 학생 수준에 맞게 쉽게 설명하는 문제를 해결하는 방향으로 기능을 선택하고 싶다.
